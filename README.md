# 711EV-Codex-Tool

`711EV-Codex-Tool` 是一款纯本地运行的 Codex 会话与供应商管理工具。它可以在同一 Codex 存储位置中识别官方账号和不同中转供应商的历史会话，并完成供应商切换、会话复制、迁移、同步及清理。

项目基于 Tauri 2、Vue 3、TypeScript 和 Rust，支持 Windows 10、Windows 11 与 macOS。作者：711EV。

## 功能概览

### 存储位置与供应商

- 自动发现 `CODEX_HOME`、默认 `~/.codex`、运行中的 Codex/ChatGPT 客户端及受支持切换工具使用的存储位置。
- 在已发现的多个存储位置之间切换；只有一个位置时，切换按钮保留但不可用。
- 从主 `config.toml` 和本地 rollout 中识别官方供应商、当前中转供应商及历史中转供应商。
- 添加、编辑和保存中转供应商，管理供应商标识、API 请求地址与 API 密钥。
- 提供 711EV 配置预填，也允许继续修改预填内容。
- 在官方 OAuth 登录与已配置的中转供应商之间切换。

### 会话管理

- 按供应商查看未归档主会话、归档会话和子会话。
- 按会话标题、项目路径或 Thread ID 搜索。
- 将能够识别归属关系的子会话折叠到主会话下，并显示子 agent 名称；名称未知时显示“未命名”。
- 把其他供应商的主会话复制到当前供应商，来源会话保持不变。
- 把其他供应商的主会话迁移到当前供应商，成功后删除来源会话。
- 双向同步“来源已更新”和“副本已更新”的关联会话，不额外创建第三条会话。
- 清理当前供应商中的已归档会话或未归档子会话。

### 客户端体验

- 首次启动、切换供应商、切换存储位置和手动刷新时重新扫描本地状态。
- 耗时扫描与会话操作在后台执行，减少界面未响应。
- 复制、迁移或供应商切换完成后，由用户决定是否重启 Codex 客户端。
- 支持应用内检查更新，并展示项目 GitHub Star 数量。

## 快速开始

1. 启动工具，等待存储位置、供应商和本地会话扫描完成。
2. 在顶部确认当前存储位置；存在多个已发现位置时可进行切换。
3. 在左侧确认当前正在使用的供应商。需要使用新中转时，先添加供应商并保存配置，再点击对应的切换按钮。
4. 如需恢复其他供应商中的会话，在左侧选择来源供应商，在中间勾选状态为“可复制”的主会话。
5. 确认右侧的来源供应商与目标供应商，然后选择“复制”或“迁移”。目标始终是当前正在使用的供应商。
6. 复制后的任意一侧产生新内容时，切换到需要接收更新的一侧并使用“同步会话”。

> 本工具不是备份软件。执行迁移或清理前，请确认不再需要将被删除的会话。

## 供应商配置与切换

### 添加或编辑中转供应商

中转供应商包含以下信息：

- 供应商：对应 `model_provider` 和 `[model_providers.<供应商>]` 使用的 ID，只能包含 ASCII 字母、数字、点、短横线和下划线。
- API 请求地址：只接受 HTTPS 地址。
- API 密钥：保存在本工具的本地 SQLite 数据库中。

“使用711EV配置”会预填供应商 `711EV` 和 API 地址 `https://ai.711ev.com/v1`，预填后仍可编辑。

保存供应商不会改变当前 `model_provider`，也不会替换当前 `auth.json`。对于尚未在使用的供应商，工具会把标准 Provider 定义写入主 `config.toml`；API 密钥只会在用户明确切换到该供应商时应用。

### 切换到中转供应商

确认切换后，工具会：

1. 从本地 SQLite 读取该供应商的 API 地址与密钥。
2. 在主 `config.toml` 中新增或更新 `[model_providers.<供应商>]`，写入当前密钥，并固定使用 `wire_api = "responses"` 和 `requires_openai_auth = true`。
3. 把主 `config.toml` 顶层的 `model_provider` 设置为目标供应商。
4. 把 `auth.json` 替换为只包含当前 `OPENAI_API_KEY` 的认证文件。
5. 校验写入结果，并在完成后询问是否重启 Codex 客户端。

供应商切换只支持主 `config.toml` 明确设置：

```toml
cli_auth_credentials_store = "file"
```

使用 `keyring`、未明确设置或无法识别的认证存储方式时，工具会阻止切换，不会修改认证文件。

### 切换到官方供应商

工具会实时关注当前存储位置中的官方 OAuth `auth.json`，并为每个存储位置保留一份最近有效的官方认证快照。切换回官方供应商时：

1. 将主 `config.toml` 顶层的 `model_provider` 设置为 `openai`。
2. 恢复最近保存且完整性校验通过的官方 OAuth 快照。
3. 不删除已经存在的 `[model_providers.<供应商>]` 配置。
4. 如果从未保存过官方快照，则删除当前中转使用的 `auth.json`，后续由用户在 Codex 中重新登录。

工具只修改所选存储位置的主 `config.toml`，不会修改 `work.config.toml` 等 Profile 配置或项目级覆盖配置。

### 写入安全

`config.toml` 与 `auth.json` 的切换采用原子替换，并记录本地事务状态。若程序在两个文件写入之间意外退出，下次启动会尝试继续完成或回滚未完成的切换，避免长期留下供应商与认证不一致的状态。

配置写入磁盘后，即使关闭本工具也会继续生效。Codex 客户端需要重启后读取新配置；CLI 会在下一次启动时读取新配置。

## 会话操作

| 操作 | 来源会话 | 目标会话 | 关联关系 |
| --- | --- | --- | --- |
| 复制 | 保留 | 创建新 Thread | 保留，可继续双向同步 |
| 迁移 | 成功后删除 | 创建新 Thread，并标记为“当前” | 不保留 |
| 同步 | 保留原 Thread ID | 保留原 Thread ID并更新内容 | 继续保留 |

### 复制

复制通过 Codex App Server 的 `thread/fork` 创建新的 Thread ID，并将新会话归入当前供应商。来源会话、来源 Thread ID、供应商和 rollout 均保持不变。

复制完成后，工具会保存来源与副本的关联关系。只要其中一侧单独产生新内容，就可以通过“同步会话”更新另一侧。

### 迁移

迁移会先在当前供应商创建并验证新会话，验证成功后再删除来源供应商中的原始会话。迁移后的目标会话显示为“当前”，不会保留可同步的复制关系。

### 同步会话

“同步会话”只在当前正在使用的供应商中显示，并且只处理仍然有效、未归档且状态为“来源已更新”或“副本已更新”的会话：

- 来源已更新：使用来源的最新内容更新现有副本。
- 副本已更新：使用副本的最新内容更新现有来源会话。
- 两侧都已更新：视为冲突并跳过，不自动覆盖任意一侧。

同步保留两侧原有 Thread ID。来源或副本任意一侧一旦归档，工具会解除关联；以后即使从归档中还原，也不会恢复原关联关系。

### 清理会话

- 清理归档：永久删除当前所选供应商中的已归档会话。
- 清理子会话：永久删除当前所选供应商中的未归档子会话，不影响其所属主会话。

清理前会展示待删除数量和具体条目。若本地 rollout 已经不存在，则按已删除处理，不计为失败。

## 会话状态

| 状态 | 含义 |
| --- | --- |
| 可复制 | 其他供应商中的未归档主会话，可以复制或迁移到当前供应商 |
| 当前 | 会话属于当前正在使用的供应商 |
| 已归档 | 本地归档会话，不参与复制或同步 |
| 子会话 | 子 agent 等内部会话，不参与复制或同步 |
| 无效 | rollout、供应商或关联信息不完整，无法安全操作 |
| 已复制 | 来源会话已经存在经过验证的副本 |
| 副本 | 工具创建并验证过的目标会话 |
| 来源已更新 | 复制后来源会话产生了新内容 |
| 副本已更新 | 复制后目标副本产生了新内容 |

这些状态会根据本地文件和复制关联重新计算，不以界面缓存作为最终结果。

## 本地数据与隐私

正式版会在主程序或 macOS App 所在目录旁创建 `CodexLocalSync.data`。本地开发时，该目录位于项目根目录：

```text
CodexLocalSync.data/
├─ app.sqlite                 # 存储位置、供应商配置、API 密钥和会话关联
├─ app.sqlite-wal             # SQLite 运行文件，存在时请与主数据库一并保留
├─ app.sqlite-shm             # SQLite 运行文件，存在时请与主数据库一并保留
├─ auth-snapshots/            # 按存储位置保存的最近有效官方 OAuth 快照
├─ transactions/              # 供应商切换期间的临时事务文件
└─ locks/                     # 防止同一存储位置被并发写入的锁文件
```

- API 密钥保存在本地 SQLite 中，数据库本身不加密；供应商生效时，同一密钥还会写入主 `config.toml` 的 `experimental_bearer_token` 和 `auth.json` 的 `OPENAI_API_KEY`。请妥善保管 `CodexLocalSync.data` 与对应的 `CODEX_HOME`。
- 官方 OAuth 快照包含敏感登录凭据。工具会限制快照与事务文件的本地访问权限，不会修改整个 `CODEX_HOME` 的权限。
- `transactions` 中的正常完成项会自动删除；意外中断时可能暂时保留，以便下次启动恢复事务。
- 工具数据库不保存聊天正文。聊天内容只在本机 Codex rollout 之间处理，不会由本工具上传到第三方服务。
- 会话复制和迁移不会携带 `auth.json`、API 密钥、Skills、Plugins 或其他 Codex 扩展配置。
- 顶部外部链接和 GitHub Star 展示会访问对应网站或 GitHub 接口；会话扫描与处理本身在本机完成。

## 平台与限制

- 支持 Windows 10、Windows 11 和 macOS；macOS 构建为 Intel 与 Apple Silicon 通用版本。
- 当前只能自动发现存储位置，暂不支持手动添加任意 `CODEX_HOME`。
- 目标供应商始终是当前正在使用的供应商，不能在复制或迁移时临时选择其他目标。
- 只复制来源为 CLI 或 Codex 客户端的未归档主会话，不复制子会话。
- 不支持恢复 ChatGPT 模式中的云端聊天记录。
- 只能处理本机仍然存在的 Codex rollout；已经彻底删除且没有本地路径引用的历史会话无法恢复。
- 两侧同时更新时不会自动合并，需要用户自行决定保留哪一侧内容。
- 供应商切换只修改主 `config.toml`；Profile 或项目级配置可能继续覆盖最终生效值。
- 会话写操作需要 Codex 客户端释放相关文件。工具会先尝试正常退出客户端，失败时再由用户确认是否强制退出。
- 本工具不会主动关闭正在运行的 CLI；已经启动的 CLI 进程不会自动重新加载配置。

## 本地开发

需要 Node.js 20、Rust stable 及对应平台的 Tauri 2 构建环境：

```bash
npm install --no-package-lock
npm test
npm exec vue-tsc -- --noEmit
npm exec vite -- build
cd src-tauri
cargo fmt --check
cargo test
cargo check
```

完整桌面构建使用：

```bash
npm run build
```

该脚本会执行 TypeScript 检查、Vite 构建和 Tauri 桌面打包，并自动将补丁版本号增加一位；构建失败时恢复原版本文件。桌面打包需要提供 Tauri 更新签名私钥，私钥不得提交到仓库。

- 前端静态资源：`build/`
- 本地预览程序：`dist/`
- Tauri 原始构建产物：`src-tauri/target/`
